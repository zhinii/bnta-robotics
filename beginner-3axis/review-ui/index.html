Robot Lab responsive UI audit

19 October 2026. Screenshot and interaction audit of the three-axis module across Learn, Explore, Challenge, and Design. Existing machine behavior and learner work were preserved.

Open local application · Click a screenshot for the full-size capture.

Implemented

  • One contextual panel: Guide, Controls, or Program. The robot has its own unobstructed scene area.
  • Move, Record, and program playback actions stay outside scrolling content. Stop remains in the header.
  • Compact phone XYZ fields; a dedicated short-landscape jog arrangement; tablet and desktop layouts.
  • Current coordinates and task coordinates live in scene-edge strips. View settings are grouped in one menu.
  • Help, history, replay, and optional AI are behind a labelled question-mark button. Instructions remain readable without permanent helper chrome.
  • Practice setup remains visible before controls open. Verified actions mark Guide and explain how to continue.
  • Specific movement failure feedback is shown next to the controls. The practice reset confirmation now uses an in-app dialog and preserves a program copy.
  • Readable text, 44px minimum action targets (48px for coarse pointers), visible focus, safe-area padding, and high-contrast selected/action/error states.

Verification

  • 110 automated model, motion, storage, curriculum, and geometry tests passed.
  • All seven lesson DOM journeys passed, including panel switching and practice confirmation.
  • Browser operated: XYZ movement, joint motion, jog, recording, selecting a program position, testing, pause, stop, practice setup, lesson completion guidance, view toggles, design fields, and invalid-target recovery.
  • Viewport audits: 1440×900, 820×1180, 390×844, 320×568, and 844×390. No horizontal page overflow in the measured cases.
  • English and Chinese phone interfaces checked. Visible action targets measured at least 44×44 CSS pixels; inline vocabulary links are the intentional exception.
Remaining validation: These are desktop-browser viewport tests, not hands-on iPhone/Android/iPad testing. Physical touch accuracy, the on-screen keyboard, notches, and real-device rendering performance still need device acceptance. The local Qwen key is unavailable, so live AI replies were not tested. No deployment or GitHub push was performed.
